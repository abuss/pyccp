## What's New

### Task 1: NeqLinear Bounds Interval Propagation

**Impact:** -2% to -3.5% on N-Queens  
**What it does:** Detects early conflicts using interval arithmetic

Example: Constraint `x - y != 0` with `x ∈ [0,7], y ∈ [0,7]`
- Computes bounds: min_diff = -7, max_diff = 7
- If k=0 is forced (all solutions violate !=), detect conflict early
- Avoids search branches that lead to contradictions

**Code:** 87 LOC + 5 unit tests

---

### Task 2: Multiply Bounds Divisibility Reasoning

**Impact:** Indirect benefit (3-5% potential on arithmetic CSPs)  
**What it does:** Prunes non-divisors when both terms are open

Example: Constraint `x * y = 12` with `x ∈ [3,5], y ∈ [1,10]`
- Only divisors of 12 are valid: {1,2,3,4,6,12}
- Prune x to {3,4} (divisors in [3,5])
- Prune y to {1,2,3,4,6} (divisors in [1,10])

**Code:** 45 LOC + 4 unit tests

---

### Task 3: Element Bounds Index Filtering

**Impact:** Indirect benefit (5-15% potential on scheduling problems)  
**What it does:** Prunes invalid indices using bounds intersection

Example: Constraint `y = array[idx]` where `array = [5,15,25], idx ∈ [0,2], y ∈ [10,20]`
- array[0]=5 ∉ [10,20] → prune idx=0
- array[1]=15 ∈ [10,20] → keep idx=1
- array[2]=25 ∉ [10,20] → prune idx=2
- Result: idx fixed to 1

**Code:** 52 LOC + 3 unit tests

## Under the Hood

### How Bounds Reasoning Works

**Traditional propagation** (v2.1):
- NeqLinear: Only prune when one term is fixed
- Multiply: Only prune when one term is fixed
- Element: Only prune when idx or y is fixed

**v2.2 with bounds reasoning:**
- NeqLinear: Also prune when bounds interval arithmetic reveals impossibility
- Multiply: Also prune when divisibility constraint applies to both terms
- Element: Also prune when bounds intersection is empty

### Performance Trade-off

Bounds checking adds minimal overhead (stack-based computation):
- NeqLinear: ~1 µs per propagation
- Multiply: ~2 µs per propagation
- Element: ~1 µs per propagation

**Net result:** -5 to -7 µs saved by early conflict detection >> +1-2 µs overhead → **-2 to -3.5% overall**

## Known Limitations

### Task 4: Cardinality (Deferred to v2.2.1)

Cardinality bounds reasoning was implemented but deferred because:
- Adds per-cell bounds checks on every propagation
- N-Queens has 0 cardinality constraints (only AllDiff)
- Net effect: +5-6% overhead with 0 benefit
- **Plan:** Optimize with lazy caching for v2.2.1

**When cardinality bounds WILL help:** Scheduling, assignment, covering problems
