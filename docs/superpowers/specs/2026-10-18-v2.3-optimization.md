## Executive Summary

v2.3 adds **cost tracking and branch-and-bound optimization** to pyccp's solver. Problems like TSP, Knapsack, and Job Scheduling require finding not just *any* feasible solution, but the *best* one under a cost metric. v2.3 enables this via:

1. **Cost cells** — Integer variables representing objective function value
2. **Cost variable tracking** — Solver maintains best-so-far cost and prunes search branches exceeding it
3. **Branch-and-bound search** — DFS with dynamic bound updates, integrated into `solve()` and `solve_all()`
4. **Three example problems** — TSP, Knapsack (0/1), Job Scheduling (makespan minimization)

The architecture keeps Rust owning the solver, propagators, and cost tracking; Python owns the problem formulation and result interpretation.

---

## Scope

### In Scope

- Cost variable tracking (single cost cell per problem)
- Branch-and-bound via dynamic best-so-far pruning
- `Store.set_objective(cell: int, minimize: bool)` Python API
- Cost extraction from solutions
- Three runnable examples: TSP, Knapsack, Scheduling
- Benchmarks comparing v2.2 (no optimization) vs v2.3 (with pruning)

### Out of Scope

- Multiple objectives / Pareto frontier
- LP solvers or continuous relaxation
- Warm-start from heuristic solutions
- Symmetry breaking
- Custom branching heuristics (variable/value ordering remains DFS)

## Architecture

### Conceptual Model

A problem defines:
- **Variables** — decision variables with integer domains
- **Constraints** — feasibility rules (handled by existing propagators)
- **Objective** — a cost cell and a sense (minimize or maximize)

**Search flow:**
1. Solver maintains `best_cost: Option<i64>` (None = no feasible solution yet)
2. At each node, if current lower/upper bound exceeds best_cost, prune the branch
3. When a solution is found (all variables fixed), update best_cost and continue searching
4. Return the solution(s) with optimal cost

### Rust-side Cost Tracking

**Store changes:**
- Add field `objective: Option<(usize, bool)>` where `usize` = cell index, `bool` = is_minimize
- Add field `best_cost: Option<i64>` tracking the best solution found so far

**Solver changes:**
- Add method `set_objective(cell: usize, minimize: bool) -> Result<(), Conflict>`
- Modify `collect()` (solve_all internals) to:
  - Check cost bounds before recursing
  - Update best_cost when a solution is found
  - Prune branches where cost exceeds best_cost

**Propagator interface:** No changes — cost tracking is solver-level, not propagator-level.

### Python-side API

```python
class Store:
    def set_objective(self, cell: int, minimize: bool) -> None:
        """Set the objective: minimize (True) or maximize (False) the value in cell."""
        self._core.set_objective(cell, minimize)
    
    def best_cost(self) -> Optional[int]:
        """Return the best cost found so far, or None if no solution yet."""
        return self._core.best_cost()
```

## Problem Models

### TSP (Travelling Salesman Problem)

**Formulation:** Find shortest Hamiltonian cycle in a complete graph.

- **Variables:** `tour[0..n-1]` — permutation of nodes
- **Constraints:**
  - `AllDiff(tour)` — each node visited once
  - Implicit: edges follow adjacency
- **Cost:** Sum of edge weights: `cost = sum(dist[tour[i]][tour[i+1]] for i in 0..n-1)`
- **Objective:** Minimize cost
- **Example:** n=5 cities, symmetric distances, cost ≈ 12–20 for random distances

### Knapsack (0/1 Knapsack Problem)

**Formulation:** Select items to maximize value under weight constraint.

- **Variables:** `selected[0..n-1]` ∈ {0, 1} — item included or not
- **Constraints:**
  - `LinearEq([(i, weight[i]) for i in items], <=, capacity)` — total weight ≤ W
- **Cost:** `value = sum(value[i] * selected[i])`
- **Objective:** Maximize value
- **Example:** n=10 items, capacity=30, values/weights from problem data

### Job Scheduling (Makespan Minimization)

**Formulation:** Assign jobs to machines to minimize completion time of last job.

- **Variables:** `machine[0..n-1]` — which machine each job runs on
- **Constraints:**
  - `AllDiff(machine) | if jobs < machines` OR distribute evenly if jobs ≥ machines
  - Implicit: job durations, machine availability
- **Cost:** `makespan = max(sum(duration[j] for j if machine[j] == m) for m in machines)`
- **Objective:** Minimize makespan
- **Example:** 8 jobs, 3 machines, durations vary, optimal ≈ 12–16

## Known Ceilings & Future Work

- **Single objective:** Multi-objective optimization deferred to v3
- **Greedy B&B only:** No LP relaxation or advanced bounding
- **Sequential search:** Rayon parallelization of enumeration deferred
- **No warm-start:** Problems must enumerate from root; good heuristics speed future
- **No symmetry breaking:** TSP will search many equivalent tours
